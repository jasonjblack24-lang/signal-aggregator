# Signal Aggregator

A multi-agent account intelligence pipeline that reads account data, catches early signals, forms hypotheses about which accounts need attention, and delivers a ranked morning briefing to Slack. It then scores its own accuracy against a labeled key.

The design goal is to mimic how a strong account owner operates: a single signal wakes the system, it pulls threads across every available data source, and it either surfaces a hypothesis worth acting on or stays quiet until the picture clarifies.

## Pipeline

```
generate_data.py      → simulated account dataset (usage, activity, tickets)
        ↓
signal_extractor.py   → derived per-account metrics + a structured signal summary
        ↓
hypothesis former     → reasons over signals + playbooks, emits ranked verdicts
        ↓
message-composer      → renders the daily hypotheses into a scannable Slack briefing
        ↓
slack_deliver.py      → posts the briefing to a Slack webhook
        ↓
eval_harness.py       → scores verdicts vs. a labeled key (precision / recall / F1)
```

The reasoning steps (hypothesis former, message composer) run as Claude Code subagents rather than hardcoded API calls, see `.claude/agents/message-composer.md` for one of the agent definitions. The Python scripts handle deterministic work (data, metrics, delivery, scoring); the agents handle judgment.

## What's interesting here

- **Separation of judgment from mechanics.** Deterministic metric extraction and delivery live in Python; the pattern-matching judgment lives in playbooks (`playbooks_consolidated.md`, `playbooks/`) that an agent acts on.
- **Observational data, separate answer key.** `generate_data.py` embeds behavioral patterns into the data without labeling them; the labels live in a separate `evaluation_key.json` used only by the eval harness. The agent never sees the answer key.
- **The pipeline grades itself.** `eval_harness.py` reports strict and lenient precision, recall, F1, and a per-pattern breakdown of misses worth reviewing.

## Quick start

```bash
# 1. Generate the simulated dataset
python3 generate_data.py --date 2026-05-01

# 2. Extract signals
python3 signal_extractor.py --as-of-date 2026-05-01

# 3. (Run the hypothesis former / message-composer agents in Claude Code)

# 4. Deliver to Slack  (set SLACK_WEBHOOK first, or use --dry-run)
python3 slack_deliver.py --date 2026-05-01 --dry-run

# 5. Score the run against the evaluation key
python3 eval_harness.py --hypotheses output/hypotheses_2026-05-01.json
```

Copy `.env.example` to `.env` and set `SLACK_WEBHOOK` for live delivery. The `data/` and `output/` folders ship with a sample run (as-of 2026-05-01) so you can inspect real inputs and outputs without running anything.

## Layout

```
generate_data.py             simulated dataset generator
signal_extractor.py          per-account metrics + signal summary
slack_deliver.py             Slack webhook delivery
eval_harness.py              precision / recall / F1 scoring
playbooks_consolidated.md    the pattern-matching library agents act on
playbooks/                   individual playbook definitions
.claude/agents/              Claude Code subagent definitions
data/                        simulated inputs + evaluation key
output/                      sample run outputs (signals, hypotheses, briefing, eval)
```

## Note on data

The entire dataset is synthetic — company names, ARR, contacts, and usage are fictional and generated by `generate_data.py`.
